# Ядро Evactix

Хранилище событий и планов и первые сборщики. Сторож Ана — отдельный проект рядом, в папке `ana/`. Модель данных — документ «ТЗ ядра Evactix: модель данных».

## Состав

| Модуль | Что делает |
|---|---|
| `evactix/migrations/` | Схема: `events` (гипертаблица TimescaleDB, сжатие через 30 дней), `plans`, справочники, журнал отказов, журнал запусков, роли |
| `evactix/model.py` | Конверт события, план, 10 типов значений |
| `evactix/validate.py` | Запреты на входе: физлица и ИП, реквизиты, email и телефоны, свободный текст, неизвестные метрики |
| `evactix/store.py` | Запись: дедупликация, поправки через `supersedes`, подпись цепочки по источнику, сырые данные на диске |
| `evactix/collectors/` | ЦБ (курсы, металлы, ключевая ставка), производственный календарь, астрономия, Met Norway, USGS, GDACS |
| `evactix/runner.py` | Планировщик сборщиков |

## Роли в базе

- `evactix` — владелец, только миграции.
- `collector` — читает справочники, дописывает события и планы. Ни `update`, ни `delete` по данным.
- `ana` — только чтение; ключ выдаётся отдельному проекту Аны.

Пароли `collector` и `ana` генерируются на сервере при первой выкатке и лежат в `/opt/evactix/.env`.

## Выкатка

Сама после слияния изменений в `core/` в `main`: workflow «Выкатка ядра» прогоняет тесты, собирает образ на сервере, применяет миграции, перезапускает сборщики.

## Тесты

Нужен локальный PostgreSQL 16 с TimescaleDB 2.17:

```
pip install -e ".[test]"
TEST_ADMIN_DSN="host=127.0.0.1 port=5432 user=evactix dbname=postgres" python -m pytest -q
```
