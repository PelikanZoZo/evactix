# Ана

Анализатор Надёжности и Аномалий — сторож рядом с ядром Evactix. Отдельный проект: свой код, свой образ,
свой compose-проект `evactix-ana` на сервере, своё состояние. Обновляется и перезапускается, не трогая ядро.

## Связь с ядром

- Сеть ядра `evactix-core` — Ана видит базу (`db`) и входную точку (`edge`).
- Роль `ana` в базе ядра — только чтение. Ключ выдаёт ядро (`ANA_DB_PASSWORD` в `/opt/evactix/.env`),
  при выкатке он копируется в `/opt/evactix-ana/.env`.
- Читает: `sources`, `collector_runs`, `rejects`, `events`, `plans`. Ничего не пишет в ядро.
- Своё состояние (какие тревоги открыты, когда отправлена сводка) — SQLite в томе `anastate`.

## Что проверяет каждые 5 минут

| Проверка | Тревога |
|---|---|
| Диск | 🟠 от 70%, 🔴 от 85% |
| База ядра | 🔴 недоступна |
| Входная точка | 🔴 не отвечает |
| Свежесть источника | 🔴 нет успешного сбора дольше `max_age` источника |
| Ошибки сборщика | 🟠 три подряд |
| Валидатор | 🟠 20+ отказов за час по источнику |

Новая тревога — сразу; если не проходит — напоминание раз в 6 часов; когда прошла — «🟢 В норме».
Сводка за сутки — каждый день в 09:00 по Москве.

## Выкатка

Сама после слияния изменений в `ana/` в `main` (workflow «Выкатка Аны»): контрактные тесты со схемой ядра,
сборка образа на сервере, перезапуск только Аны.

## Дальше

При первом клиенте Ана переезжает на отдельный сервер (VPS-3) и вместо прямого чтения базы
смотрит на служебный эндпоинт состояния ядра.
